## 1. Executive Summary & Problem Statement Alignment

**KaljiHome** is a smart, collaborative, and clinical-safety-first healthcare management platform built for Indian older adults and their authorized Care Circles. The platform was built strictly according to the problem charter in `01_PROBLEM_STATEMENT.md` and the build brief in `MASTER_BUILD_BRIEF.md`.

Rather than acting as a cold alarm or an intrusive surveillance tool, KaljiHome centers on **older adult agency and transparent care coordination**:
1. **Elder Agency:** The older adult owns their profile (`prof_meera`), sees today's routine in clear local time (`Asia/Kolkata`), records self-reported dose actions, and can view or revoke any member's access at any time.
2. **Cryptographic Passcode Access:** Replaces insecure shared household passwords with single-use, 10-minute expiring passcodes stored as keyed HMAC-SHA256 digests.
3. **Strict Clinical Guardrails:** Never invents or autocompletes drug names or dosages; requires explicit prescription transcription and verification; distinguishes reported ingestion from biochemical certainty; transitions overdue doses past the grace period to `Unconfirmed / No status recorded` (never auto-marked skipped or taken); directs users to doctors/pharmacists rather than generating AI medical advice.
4. **Privacy-Preserving Email Reminders:** Proactively notifies Care Circle members of upcoming doses, overdue unconfirmed events, and doctor appointments using an idempotent outbox pattern, with subjects and previews strictly scrubbed of medication names, dosages, and medical diagnoses (FR-027).
5. **Traceable Care Activity Feed:** Records all medication changes, dose events, and appointments in an immutable ledger with actor attribution and timestamps.

## 4. Evaluation Evidence Across the Six Criteria

### 4.1 Criterion 1 — Code Quality
- **Architecture:** Monolithic, modular full-stack Next.js 14 (App Router) + TypeScript application.
- **Separation of Concerns:** Distinct domain services in `src/services/` (`auth`, `policy`, `invitations`, `medications`, `dose-ledger`, `appointments`, `notifications`, `timeline`), unified typed database module in `src/lib/db.ts`, and accessible UI components in `src/components/`.
- **Typing & Linting:** Strict TypeScript with zero `any` evasions in core types (`src/types/index.ts`). Next.js linter (`npm run lint`) reports:
  ```
  ✔ No ESLint warnings or errors
  ```
- **Production Build:** Next.js build (`npm run build`) generates 18 optimized static and server-rendered routes with zero errors:
  ```
  ✓ Generating static pages (18/18)
  ✓ Compiled successfully
  ```

### 4.2 Criterion 2 — Security & Trust
- **Object-Level Authorization (IDOR/BOLA Guard):** Server-side gatekeeper `can(userId, action, profileId)` evaluates active profile membership and granular permissions on every read/write.
- **Cryptographic Passcodes:** 8-character human-friendly codes (`generateInvitationCode`) stored strictly as HMAC-SHA256 digests (`computePasscodeDigest`). Plaintext codes are never stored or logged in the database.
- **Atomic Acceptance:** Passcode consumption occurs inside an atomic SQLite transaction, preventing replay attacks and race conditions.
- **Immediate Revocation:** Revoking a membership updates database status instantly, immediately blocking subsequent API calls even from active browser sessions.
- **Privacy-Preserving Messaging:** Email subjects and previews are strictly scrubbed of medication names, strengths, dosages, and medical conditions (FR-027).

### 4.3 Criterion 3 — Efficiency & Reliability
- **Relational Schema & Indexing:** Dedicated indexes on `care_memberships(profile_id, user_id, status)`, `dose_occurrences(profile_id, scheduled_local_date)`, `dose_events(occurrence_id)`, and `notification_outbox(status, scheduled_for_utc)`.
- **Bounded Horizons:** Recurrence engine generates bounded horizons (7-14 days) rather than unbounded database bloat.
- **Idempotency:** Unique constraints on `(schedule_version_id, local_occurrence_key)` and `(occurrence_id, idempotency_key)` guarantee that scheduler re-runs or duplicate network requests will never duplicate occurrences or dose records.
- **Zero Heavy Daemons:** SQLite file-based database provides zero-latency local queries and 100% self-contained reproducibility for evaluators.

## 6. How to Run & Evaluate the Demo

1. **Install Dependencies (if not already installed):**
   ```bash
   npm install
   ```
2. **Run Tests:**
   ```bash
   npm run test
   ```
3. **Start Development Server:**
   ```bash
   npm run dev
   ```
   Open `http://localhost:3000` in your browser.

4. **Recommended Evaluation Walkthrough:**
   - **Step 1 (Today Dashboard):** Observe Meera Sharma's daily routine, next scheduled dose card, and next doctor appointment.
   - **Step 2 (Persona Switching):** Use the top-right persona buttons in the header to switch between Meera (Owner), Arjun (Manager), Sunita (Caretaker), and Nisha (Read-Only). Notice how UI action buttons automatically enable/disable based on server permissions!
   - **Step 3 (Record a Dose):** As Sunita or Meera, click "Mark Taken" on a scheduled dose. Observe how the status updates to "Reported Taken by [Actor] at [Time]".
   - **Step 4 (Medications & Prescriptions):** Visit `/medications` and click "Add Medication". Verify that attempting to submit without ticking the prescription confirmation checkbox is blocked by the clinical safety guardrail!
   - **Step 5 (Care Circle & Passcodes):** Visit `/care-circle`. Click "Invite with Passcode". Enter an email (e.g. `doctor@example.com`) and click "Generate Passcode". Observe the single-use 8-character code and 10-minute timer.
   - **Step 6 (Revoke Access):** Click "Revoke Access" on an existing caretaker. Notice how their active membership is immediately terminated.
   - **Step 7 (Email Outbox / Dev Sink):** Visit `/notifications`. Inspect queued and dispatched email reminders. Click "Preview Message" to verify that medication names and diagnoses are scrubbed from subjects and previews (FR-027). Click "Process Outbox Worker" to trigger batch dispatching.
   - **Step 8 (Care Timeline):** Visit `/timeline` to inspect the complete, traceable audit trail of all actions performed.
   - **Step 9 (Safety & Trust):** Visit `/privacy` to review the legal, DPDP Act 2023 / 2025 roadmap, and clinical safety architecture.
